Policy Brief

Agent Transition Standards for Competitive AI Markets

The AI agent protocol stack addresses communication (A2A), tool access (MCP), and payments (AP2). No protocol addresses what happens when an agent transitions between platforms. EXIT fills this gap with a minimal, open, cryptographically verifiable format for portable agent departure records.

Executive Summary

The Documentation Gap

Without agent transition documentation, enterprises cannot perform due diligence, insurers cannot underwrite operations, regulators cannot audit transitions, and markets cannot price risk. EXIT provides the missing documentation layer.

Key finding: Agent transitions are already happening — without documentation, without audit trails, without standards. EXIT doesn't create agent mobility. Agent mobility already exists. EXIT makes it visible, auditable, and governable.

The Problem: Undocumented Agent Transitions

This is the equivalent of a used car market with no vehicle history reports. The transactions happen — but nobody can verify what they're getting.

Economic Consequences

  • Market friction: Receiving platforms cannot assess incoming agents
  • Adverse selection: Classic "market for lemons" (Akerlof, 1970)
  • Risk mispricing: Insurers cannot price agent-related risk
  • Lock-in inefficiency: Switching costs unrelated to quality

Compliance Exposure

  • SOC 2 / ISO 27001: Undocumented migrations create audit gaps
  • Financial regulation: Obligations follow agent history
  • EU AI Act: Documentation requirements extend to lifecycle events
  • Insurance: Underwriters need lifecycle data that doesn't exist

Proposed Standard: The EXIT Protocol

A minimal format for portable, cryptographically signed agent departure records. ~300–500 bytes. JSON-LD. Ed25519 signatures. Offline-verifiable.

Design Properties

Always Available

Transition records producible even without platform cooperation. No denial-of-documentation attacks.

Minimal Core

Seven mandatory fields. All extensions optional. Minimal integration cost and attack surface.

Cryptographically Verifiable

Ed25519 signatures. Offline verification. No dependency on external services.

Non-Custodial

No central registry. No single point of failure. No custodian liability exposure.

Standards-Aligned

JSON-LD, W3C DIDs, W3C Verifiable Credentials, KERI-compatible key management.

GDPR-Compatible

Pseudonymous identifiers. Data minimization. Functional erasure. Non-custodial architecture.

Recommendations for NIST

6.1

Include Agent Lifecycle Transitions in the Standards Framework

Agent transitions are equally critical lifecycle events requiring standardized documentation. Portable agent identity, verifiable transition records, and cryptographic continuity proofs should be within scope.

6.2

Establish Non-Blocking Transition Documentation as a Governance Principle

Operators must always retain the ability to produce a verifiable transition record regardless of platform cooperation. This prevents denial-of-documentation attacks and lock-in.

6.3

Address the Information Asymmetry Problem

Multi-party attestation, graduated trust models, structured dispute documentation, and economic mechanisms for honest reporting. The Akerlof "market for lemons" problem applies directly to agent transitions.

6.4

Build on Existing W3C Standards

Adopt W3C DIDs for agent identification. Include transition credentials in verifiable agent credentials scope. Leverage existing VC infrastructure.

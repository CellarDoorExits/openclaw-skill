## 1. Vision Consistency

**Verdict: Broadly consistent with evolutionary drift.**

All documents describe the same core architecture: a fractal triad (LOCUS/SIGNUM/SENSUS) applied across layers to produce ~21 primitives, with EXIT as the strategic wedge, HOLLOW as sovereign hosting, and the full stack building toward an agent economy with constitutional guarantees (exit rights, solvency proofs, consent, sybil resistance, legible interfaces).

**Consistent across all docs:**
- EXIT as first-ship priority
- The dependency chain: EXIT → NAME → Reputation → Insurance
- Looking Glass/Lumen as the hardware moonshot with asymmetric risk/reward
- HOLLOW = sovereign agent hosting, Hawthorn = prototype
- Resonance as Warren's research domain, not schedulable
- The flywheel concept with multiple independent engines

**Evolutionary drift (not contradictions):**
- **holos-full-synthesis** and **holos-overview** describe HOLOS as primarily a philosophical/protocol framework. The investment theses (v2, v3) and portfolio strategy reframe it as a diversified investment portfolio.
- **holos-full-synthesis** emphasizes sheaf theory, torus models, and Peircean semiotics deeply. The investment theses mention none of this — they're pure business documents. This is appropriate audience separation, not inconsistency.
- **v3** dramatically expands scope beyond software (Fool-Hardy consulting, Quesnel land, Hot Chip fry kiosk) that no other doc mentions. This is additive, not contradictory.
- **holos-integration-plan** describes a Delaware LLC entity ("Cellar Door LLC") with detailed package boundaries (@cellar-door/exit, @holos/identity, etc.). The **portfolio strategy** explicitly argues *against* a Delaware LLC, recommending BC sole proprietorship instead. **This is a direct contradiction** — see §7.

**Verdict: Significant naming inconsistencies across documents.**

| Concept | Old/Variant Names | New/Canonical Name | Which Docs Use Which |
|---------|-------------------|-------------------|----------------------|
| Agent reputation system | Signamancy, SIGNUM, MARK/WORD | **REPUTE** (not yet adopted) | full-synthesis uses "Signamancy"; theses use "Signamancy"; compact uses "Signamancy"; integration-plan uses "MARK/WORD" |

| Agent lineage | LINE, Module A lineage | **LINEAGE** (not yet adopted) | integration-plan uses "LINE"; full-synthesis uses "LINE"; theses don't reference LINE as a separate primitive |
| The protocol primitive for reputation scoring | Signamancy (the repo/rule engine) vs MARK/WORD (the primitives) | Unclear | These are conflated — Signamancy is both a repo name AND a primitive name. full-synthesis treats it as the SIGNUM layer; v2/v3 treat it as a reputation system |

**Key confusion:** "Signamancy" does triple duty:
1. The name of a GitHub repo (dogcomplex/Signamancy) — a declarative LHS⇒RHS rule engine
2. A HOLOS primitive in the SIGNUM column — how things appear/interface
3. A reputation system — agent credit bureau

These are three different things sharing one name. The theses (v2, v3) use "Signamancy" to mean the reputation/credit bureau. The full-synthesis and compact reference use it to mean the rule engine. The 7-layer ontology table places it differently depending on which doc you read.

**SEAL vs SEEL:** The earlier docs (full-synthesis, compact, overview) use "SEEL." The later docs (v2, v3) use "SEAL." The integration plan hedges with "SEAL/SEEL." No doc explains the rename.

**No doc uses "PLEDGE," "REPUTE," or "LINEAGE"** — if these are intended canonical names, they haven't propagated into any document yet.

## 7. Recommendations

### Critical fixes:

1. **Resolve the legal entity contradiction.** The integration-plan assumes a Delaware LLC ("Cellar Door LLC"). The portfolio strategy says $0 legal spend and BC sole prop. v3 mentions HoldCo + SPV for property. These three positions are incompatible. Decide which is canonical and update the others.

2. **Resolve the budget discrepancy.** Portfolio strategy assumes $12K. v3 assumes $200K. If Warren's actual available capital is $200K, the portfolio strategy is obsolete for capital allocation (though its software sequencing remains valid). Clarify the real number.

3. **Fix the Signamancy naming collision.** "Signamancy" means three different things. Recommend:
   - **Signamancy** (the repo) = the LHS⇒RHS rule engine
   - **REPUTE** or **Reputation** = the agent credit bureau concept
   - **SIGNUM** = the ontological column (interface/boundary)

4. **Standardize SEAL vs SEEL.** Pick one. SEAL appears in the later, more authoritative docs. Recommend SEAL.

5. **Update the TODO.** It's the most stale document in the group. It doesn't reflect EXIT's implementation status, the consulting priority, the NIST deadline, or the property plays. Either rewrite it to match v3's priorities, or mark it as historical.

### Structural recommendations:

6. **The Portfolio Strategy should be retired or merged into v3.** They cover overlapping ground with conflicting budgets. v3 is strictly more comprehensive. Keep the portfolio strategy's trading bot analysis (Section 5) and legal analysis (Section 3) as appendices to v3.

7. **The integration-plan is the most tactically useful document** for EXIT development specifically. Its primitive staging plan, graduation triggers, and package boundaries are not replicated elsewhere. Preserve it but update the legal entity assumptions.

8. **holos-full-synthesis and holos-compact are the philosophical/architectural references.** They don't conflict with the investment docs — they operate at a different level. Keep them as-is but note that the 7-layer ontology's upper layers (Constraint, Economics) have no development plans in any investment doc.

9. **v2 can be archived.** v3 supersedes it completely. Keep v2 for historical reference but mark it superseded.

### Naming canonicalization needed:

| Decide | Options | Recommendation |
|--------|---------|----------------|
| ZK certification primitive | SEAL vs SEEL | **SEAL** (used in latest docs) |
| Insurance product | Insurance vs PLEDGE | **Insurance** (no doc uses PLEDGE yet) |
| Reputation system | Signamancy vs REPUTE | Disambiguate: Signamancy = rule engine, new name for reputation |
| Lineage | LINE vs LINEAGE | **LINE** (used in ontology table) |
| The overall portfolio | HOLOS (protocol) vs Warren's portfolio | Clarify: HOLOS = the protocol/philosophy; the portfolio includes non-HOLOS assets |
